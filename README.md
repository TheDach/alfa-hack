# Tabular Research Agent v3

Автономный агент для одноцелевых табличных задач. Он читает `task.md`, анализирует данные, проверяет гипотезы с Qwen и локальными ML-моделями, выбирает решение по собственной валидации и сохраняет `submission.csv` рядом с условием.

**Состояние v3:** официальный результат v2 — **20.8773** (сырое значение истории 2087.732), место **92/202** при проверке 25 октября 2026 года. Цель следующей версии — не менее 28, достижение пока не подтверждено. На прежнем контроле следующего года RMSE v3 **40.153035** против **43.029244** у v2 при одинаковом бюджете 600 секунд. Локальная метрика не является официальным баллом.


## Дополнения v3

При явном переходе теста в будущий период агент сначала определяет число итераций по calibration, затем переобучает конфигурацию на fit+calibration и оценивает её на отдельной validation. Её ответы не участвуют ни в одном обучении. Резерв времени учитывает отсутствие случайного OOF при временном сдвиге.

В начале временного поиска проверяются устойчивые исторические модели. Добавлены выбираемые гипотезы дисперсии истории, изменений сопутствующих числовых характеристик и приблизительного сопоставления объектов при небольшом изменении непрерывного атрибута. Собственный таргет обучающей строки исключается из статистик и соседей. Для Macro F1 сохранены прежние порядок поиска, лимит 16 экспериментов и схема OOF v2. Новые сглаженные варианты, ускоренное разбиение и полное финальное обучение отклонены после ухудшения на внешнем контроле. Для других классификационных метрик можно проверить остановку по log loss.

Для классификации сохранено прежнее StratifiedGroupKFold-разбиение: ускоренный вариант разбиения отклонён после ухудшения на внешнем контроле. Параметры новых гипотез проходят строгую проверку планировщика Qwen.

## Быстрый запуск

Python 3.12. Команды PowerShell выполняются из корня проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe solution.py data/regression/task.md --offline --threads 4 --memory-gb 5 --time-budget 600 --max-trials 8
```

Локальный список зависимостей включает XGBoost 2.1.4.

Полный исходный список библиотек организаторов находится в `reference/requirements.txt`; при сборке именно он включается в архив. Пакеты устанавливают заранее, а не из исполняемого решения. Семейства, библиотеки которых отсутствуют локально, не добавляются в меню экспериментов.

В каталоге задачи нужны `task.md`, `train.csv`, `test.csv`, `data_dictionary.csv` и `sample_submission.csv`. Пути из Markdown разрешаются относительно файла условия; также поддерживается плоская папка с файлами тех же имён. Выходной CSV повторяет колонки шаблона, порядок тестовых строк и исходные метки классов.

## Qwen и работа без ключа

На платформе `OPENAI_API_KEY` и `OPENAI_BASE_URL` задаются окружением. В коде нет собственного ключа или жёстко заданного адреса API. Имя модели читается из `OPENAI_MODEL`, по умолчанию используется `qwen/qwen3.8-27b`.

Для локального запуска можно заполнить игнорируемый Git файл `.env` по `.env.example` или задать переменные окружения. Переменные окружения имеют приоритет над `.env`. По инструкции организаторов локальные адреса: `https://changellenge.up.railway.app/v1`, запасной `https://api.alfahack-gateway26.ru/v1`. На платформе следует использовать переданный `OPENAI_BASE_URL`.

```powershell
$env:OPENAI_BASE_URL = "https://changellenge.up.railway.app/v1"
$env:OPENAI_MODEL = "qwen/qwen3.8-27b"
# OPENAI_API_KEY задайте локально; не помещайте его в Git или архив.
.\.venv\Scripts\python.exe tools/check_api.py
.\.venv\Scripts\python.exe solution.py data/classification/task.md --threads 4 --memory-gb 5 --time-budget 900 --max-trials 10
```

При отсутствии ключа/адреса, отказе API или исчерпании локального бюджета токенов агент продолжает исследование по локальной стратегии. Флаг `--offline` явно отключает Qwen даже при наличии `.env`. Это полноценный запуск ML-пайплайна, но он не подтверждает работу API.

Ограничения планировщика: до 12 обращений, до 4096 выходных токенов на запрос, до 24000 суммарных токенов на задачу. `LLM_TOKEN_BUDGET` меняет последний предел. Денежный лимит организаторов — 600 рублей в день на команду, сброс в 03:00 МСК; стоимость запросов контролируется провайдером. В отчёте сохраняются расход токенов и обезличенные причины отказов, ключ обучающим процессам не передаётся.

## Что изменено в v2

1. **Смысловой профиль.** Qwen получает метрику, цель, требования к валидации, единицы и описания из `data_dictionary.csv`, а также структуру и пропуски признаков. При ограничении размера сначала сохраняются важные требования и описания target/категорий/признаков с пропусками. Длинные списки путей и таблицы не вытесняют смысл задачи из начала запроса.
2. **Проверка временного сдвига.** При ясном переходе дискретного временного признака вперёд, например train содержит периоды 1–5, а test — 6, агент выбирает временную валидацию. Если имеется 3–30 периодов, fit, calibration и validation разделяются по целым периодам. Схему можно задать явно через `--time-column` или `--group-column`.
3. **История повторяющихся объектов.** Для регрессии агент может найти повторяющиеся сигнатуры по смыслу описаний площади, времени постройки и категориальных характеристик. Гипотезы проходят отбор по структуре входных данных без обращения к контрольным target. Для обучающих строк групповые средние вычисляются с исключением собственной строки (leave one out); calibration/validation/test получают статистики только fit. Невстречавшиеся группы используют общий prior по fit.
4. **Residual-модель.** Проверяется отдельная гипотеза обучения отклонения от исторического среднего объекта. При предсказании базовое среднее прибавляется обратно. Это выбираемая по валидации конфигурация, а не обязательная обработка всех задач. Дополнительно можно проверить исключение числовых признаков с сильным сдвигом распределения; колонки сигнатуры объекта сохраняются.
5. **Более широкий поиск.** Сравниваются CatBoost, LightGBM, XGBoost, ExtraTrees и линейные модели. Начальное покрытие разных семейств защищает поиск от расходования всех попыток на вариации одной модели. Для LightGBM проверяются native и ordinal категории; XGBoost использует числовой энкодер; линейные модели — one-hot категории и масштабированные числовые признаки.
6. **Признаки и метрики.** Кроме частот категорий, пропусков и преобразований длинных хвостов доступны категориальные пересечения, статистики строки и проверенные числовые операции Qwen. Objective и early stopping учитывают выбранную метрику там, где семейство это поддерживает: в частности Macro F1 для CatBoost/LightGBM/XGBoost, MAE/MAPE в поддерживающих их моделях, log-target для RMSLE. Бинарные и многоклассовые вероятности приводятся к общей схеме классов.
7. **Ансамбли и OOF.** На начальной validation выбирается выпуклая смесь до четырёх моделей. При бюджете от 300 секунд и достаточном остатке времени для задач без временной схемы лучшие конфигурации могут переобучаться на 2–3 folds с out-of-fold предсказаниями; допускается до двух конфигураций. Для Macro F1 веса классов калибруются по OOF, а предсказания folds усредняются. Калибровочная OOF-метрика служит диагностикой, а не независимой итоговой оценкой.
8. **Финал при временном сдвиге.** Случайный OOF не используется после временной валидации. Выбранные модели переобучаются на всех доступных train-строках; если хватает времени, для самой весомой модели обучаются ещё до двух seeds и усредняются при сохранении выбранных весов смеси.

Списки названий public-target или готовые решения конкретного датасета в стратегии не зашиты. Данные test не содержат известных агенту правильных ответов. Гипотезы, конфигурации, калибровка и смеси выбираются по внутренним данным; общий leaderboard не возвращает обратную связь агенту во время запуска.

## Надёжность и ресурсы

Сначала агент сохраняет резервный корректный CSV, затем атомарно обновляет его по мере успешных экспериментов. Каждая проверка и финальное обучение запускаются в отдельном дочернем процессе с лимитом времени и памяти. Ошибка модели, таймаут, отсутствие API или неудачный OOF не удаляют последний корректный checkpoint. Постоянный target и постоянные признаки обрабатываются резервными моделями.

По умолчанию: 10320 секунд общего бюджета, до 24 экспериментов для регрессии и до 16 для классификации, до 900 секунд на отдельный эксперимент, 8 CPU, 27 GiB на процесс эксперимента с потомками. Импорты и чтение данных входят в общий бюджет. Резерв финального обучения меняется по измеренной стоимости моделей. Ограничения платформы на одну задачу: 3 часа, 8 CPU, 32 GB RAM.

```powershell
.\.venv\Scripts\python.exe solution.py task.md --offline --time-budget 600 --max-trials 8 --threads 4 --memory-gb 5
.\.venv\Scripts\python.exe solution.py task.md --time-column period
.\.venv\Scripts\python.exe solution.py task.md --group-column customer_key
.\.venv\Scripts\python.exe solution.py task.md --task-type regression --metric mae --target outcome
```

В `research_runs/<run>/` сохраняются отчёт, split-индексы, конфигурации, сгенерированные исходники экспериментов, логи, предсказания и модели. `latest.json` указывает на последний отчёт. `model_manifest.json`, если финальное обучение завершилось, перечисляет модели и веса, включая folds/seeds. `tools/predict.py manifest.json input.csv output.csv` использует эти сохранённые модели. Временная копия данных удаляется после завершения; `--keep-data` сохраняет её для отладки.

Статус `complete` означает, что сформировано финальное решение, `validated_checkpoint` — сохранён результат эксперимента при нехватке ресурсов для финала, `fallback` — только резервный ответ. Ни один из этих локальных статусов не является официальной оценкой платформы.

## Тесты и сравнение версий

Запускайте именно каталог `tests`, чтобы pytest не собирал старые копии тестов из `work`:

```powershell
.\.venv\Scripts\python.exe -m pytest tests -q
```

Тесты проверяют схему CSV, порядок ID, метки классов, пропуски, неизвестные категории, метрики, временные split, train-only статистики, ансамбли, сериализацию, таймауты, лимиты Qwen и плоский архив. Итоговое количество пройденных тестов и текущие метрики следует брать из отчёта конкретного прогона, а не из ранее сохранённого результата v1.

Локальный benchmark по умолчанию отключает API:

```powershell
.\.venv\Scripts\python.exe tools/benchmark.py --tasks classification --threads 4 --memory-gb 5 --time-budget 900 --max-trials 10 --output reports/benchmark_v2
.\.venv\Scripts\python.exe tools/benchmark.py --online --threads 4 --memory-gb 5 --time-budget 900 --max-trials 10 --output reports/benchmark_v2_online
```

Он отделяет 20% исходного train с seed `20261023`; правильные ответы внешнего holdout не передаются агенту. RandomForest с фиксированными параметрами служит локальным ориентиром, а не официальным baseline. Для проверки поведения при сдвиге по времени требуется отдельное forward-сравнение, поскольку случайный внешний holdout не имитирует новый период. Официальное улучшение v1 → v2: 13.9476 → 20.8773. Для v3 требуется отдельная проверка платформой. Многократно просмотренный при разработке holdout следует считать диагностическим.

## Сборка и платформа

```powershell
.\.venv\Scripts\python.exe tools/build_submission.py
```

Сборщик создаёт `dist/submission.zip` и `dist/submission.sha256`, проверяет синтаксис Python, целостность ZIP, допустимый состав и отсутствие ключей. Корень ZIP содержит `solution.py`, модули `automl_*.py` и предоставленный организаторами `requirements.txt`. Импорты `research.*`, включая строку запуска дочернего процесса, преобразуются в плоские импорты. Вложенные каталоги с пакетами платформа не копирует.

`.env`, данные, модели, `.venv`, тесты, документация и логи в ZIP не включаются. Платформа запускает `python3 solution.py task.md` и оценивает `submission.csv` рядом с условием. После старта разрешён только предоставленный прокси Qwen; скачивание внешних данных, предобученных весов или установка пакетов из решения не используются.

Перед отправкой проверьте тесты, SHA256 и сравнительные метрики. Сборка сама ничего не загружает. На команду доступны три отправки в день с обновлением лимита в 00:00 МСК. Отправки v1 и v2 сохранены отдельно; новая v3 требует отдельного подтверждения пользователя. Постановка в очередь означает ожидание проверки, а результат подтверждается завершённой оценкой платформы.

## Балл и поддерживаемые задачи

Формулы приложения 3 для public:

```text
S_reg = 100 * max(0, 1 - RMSE / B_RMSE)
S_cls = 100 * max(0, (MacroF1 - B_F1) / (1 - B_F1))
score = (S_reg + S_cls) / 2
```

Нормализованный score находится в диапазоне 0–100. Значения `B_RMSE` и `B_F1` организаторов на том же скрытом test неизвестны; официальный score нельзя восстановить из локального RandomForest. Для первой отправки история показывала `1394.764`, пользователь уточнил значение общего рейтинга `13.9476`. Эти два представления и их источники сохранены в отчётных JSON. «Лучшее решение» — статус в истории собственной команды.

Поддерживаются одноцелевая регрессия, бинарная и многоклассовая классификация. Метрики: RMSE, RMSLE, MAE, MAPE, R2, Macro F1, Weighted F1, Accuracy, ROC AUC, Log Loss, Average Precision. Для бинарной вероятностной метрики в колонку target записывается вероятность класса с большим значением в сортировке меток; определение положительного класса должно соответствовать условию. Многоклассовый CSV с отдельной вероятностью каждого класса, multioutput, ранжирование, кластеризация и нетабличные данные не реализованы.

Private использует две новые задачи с неизвестными заранее метриками. Успех на public или локальной валидации не гарантирует тот же результат на private. В новых условиях агент получает тот же набор файлов и работает без ручной настройки.
