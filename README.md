# Tabular Research Agent

Автономное решение табличных задач по описанию в Markdown. Единственная точка входа — `solution.py`; интерфейс совместим с опубликованным `baseline.py`.

```powershell
python solution.py C:\path\to\task.md
```

Каталог задачи содержит `train.csv`, `test.csv`, `data_dictionary.csv`, `sample_submission.csv`. Пути в Markdown разрешаются относительно самого файла задачи. Если материалы скачаны в одну папку без исходных подкаталогов, используются файлы с теми же именами. Результат — `submission.csv` рядом с `task.md`, с колонками шаблона, исходными метками классов и порядком строк теста.

## Установка

Python 3.12:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
```

В `requirements.txt` находится только используемое подмножество разрешенных организаторами библиотек с исходными версиями. Полный список сохранен в `reference/requirements.txt`, неизмененный агент организаторов — в `reference/baseline.py`. В архив отправляется код; датасеты, веса моделей, виртуальное окружение и ключи не включаются.

## Доступ к Qwen

Нужны три выданных организаторами значения:

```powershell
$env:OPENAI_API_KEY = "ключ команды"
$env:OPENAI_BASE_URL = "адрес OpenAI-совместимого API"
$env:OPENAI_MODEL = "точное имя выданной модели"
python solution.py data/regression/task.md
```

Можно заполнить `.env` рядом с `solution.py` по примеру `.env.example` либо передать `--env-file`. Переменные окружения имеют приоритет. Код не выбирает другого провайдера или модель. Для исключения API-вызовов есть `--offline`.

При отсутствии доступа, отказе API или исчерпании бюджета исследование продолжается по локальной стратегии. Такой запуск проверяет ML-пайплайн; он не подтверждает работу реального Qwen. Состояние API и расход токенов доступны в отчете. Лимиты: 12 обращений, до 1200 выходных токенов на запрос, до 24000 суммарных токенов. `LLM_TOKEN_BUDGET` меняет общий предел. Денежный лимит 600 рублей контролируется провайдером: тариф в материалах не указан, пересчет токенов в рубли не делается.

## Исследование

1. Агент читает условие и словарь, определяет target, тип задачи, метрику, категории и схему ответа. Идентификаторы исключаются из признаков.
2. Сразу сохраняет корректный резервный CSV по среднему, медиане или априорным вероятностям. Обновления файла атомарны.
3. Выделяет fit, calibration и validation. Классификация использует стратификацию с сохранением редких классов в fit. Совпадающие строки признаков при заметной доле дубликатов группируются. Частоты категорий, заполнение пропусков и прочие преобразования обучаются только на fit.
4. Обучает исходный CatBoost. Затем выбирает гипотезы по истории метрик и ошибок. Qwen получает условие, профиль, результаты и допустимые конфигурации; может предложить новые отношения, разности, суммы, произведения и преобразования числовых признаков. Внешние тексты не исполняются как инструкции.
5. Генерирует отдельный Python-файл эксперимента из проверенной конфигурации и запускает его в дочернем процессе. Исполняемый код строится локальным шаблоном; произвольный код из ответа LLM не запускается. Неудача одного эксперимента не удаляет последний корректный ответ.
6. Сравнивает CatBoost, LightGBM, ExtraTrees и линейные модели; проверяет глубину, регуляризацию, балансировку классов, преобразования, длительность бустинга и признаки. Калибровка решений для Macro F1 использует calibration, а сравнение гипотез — отдельный validation.
7. Проверяет смеси двух лучших моделей, затем переобучает выбранные конфигурации на всех доступных обучающих строках. Сохраняет модели и итоговый CSV.

Выбор гипотез не использует правильные ответы test или публичный leaderboard. Гиперпараметры и признаки не привязаны к названиям публичных target. В offline-режиме доступен набор проверяемых направлений и адаптивное продолжение лучшей модели; для новых смысловых гипотез и признаков требуется подключение Qwen.

## Лимиты и диагностика

По умолчанию: 10320 секунд на весь запуск, до 8 CPU, 27 GiB для процесса эксперимента и его потомков, до 16 экспериментов. Часть времени резервируется под итоговое обучение. Время чтения данных и импорта входит в общий бюджет. На каждом шаге проверяются остаток времени и память; превышение лимита останавливает дочерний процесс. Внешний жесткий лимит платформы остается окончательным ограничением.

```powershell
python solution.py data/classification/task.md --offline --time-budget 600 --max-trials 8
python solution.py task.md --group-column customer_id
python solution.py task.md --time-column event_time
python solution.py task.md --task-type regression --metric mae --target outcome
```

Если условие явно требует time split или групповую валидацию и называет колонку в обратных кавычках, агент выбирает ее автоматически. Флаги позволяют задать схему явно для других формулировок. Агент не угадывает постоянный идентификатор сущности по уникальному `id`. Для стандартных задач ручные настройки не нужны. Не следует выбирать схему валидации по результатам внешнего holdout.

В `research_runs/<run>/` сохраняются `report.json`, индексы split, исходники экспериментов, конфигурации, процессные логи, проверочные предсказания и модели. `latest.json` указывает на последний отчет. Матрица ошибок, F1 каждого класса или квантили остатков входят в историю. API-ключ не передается обучающим процессам и не записывается в отчет. Промежуточная копия данных удаляется после завершения; `--keep-data` сохраняет ее для отладки.

Успешный статус `complete` означает завершенное финальное обучение; `validated_checkpoint` — сохраненную модель по fit при нехватке ресурсов для финального обучения; `fallback` — только резервный ответ. Для постоянного target предусмотрен `constant_target`.

## Поддерживаемые задачи

Одноцелевая регрессия, бинарная и многоклассовая классификация. Метрики: RMSE, RMSLE, MAE, MAPE, R2, Macro F1, Weighted F1, Accuracy, ROC AUC, Log Loss, Average Precision. Для вероятностных бинарных метрик в колонку target записывается вероятность класса с большим значением в сортировке меток. Ее следует сверить с определением положительного класса в условии. Для R2 нужны хотя бы две независимые строки валидации.

Многоклассовый CSV с отдельной вероятностью каждого класса, multioutput, ранжирование, кластеризация и нетабличные форматы не реализованы. Приватные задачи в PDF не раскрыты; совместимость с произвольным неизвестным форматом обещать нельзя. Неподдерживаемая схема вызывает явную ошибку.

## Проверки и тестовая оценка

```powershell
python -m pytest tests -q
python tools/benchmark.py --time-budget 600 --max-trials 8 --threads 8
```

Benchmark отделяет 20% исходного train с seed `20261023` и не передает эти цели агенту. Из оставшихся 80% агент строит собственные fit/calibration/validation. Эталон сравнения — заранее фиксированный RandomForest с 200 деревьями, глубиной 12, `min_samples_leaf=2`, seed 42 и тем же внешним holdout. Его параметры не подбираются по контрольной выборке. Публичные test организаторов в этом сравнении не используются.

Этот RandomForest — локальный ориентир, не официальный baseline. Опубликованный `baseline.py` вызывает LLM и не фиксирует ML-модель или значения метрик. Для официального балла нужны результаты организаторского бейзлайна на том же скрытом test.

Точные формулы приложения 3:

```text
S_reg = 100 * max(0, 1 - RMSE / B_RMSE)
S_cls = 100 * max(0, (MacroF1 - B_F1) / (1 - B_F1))
score = (S_reg + S_cls) / 2
```

Пересчет с известными метриками:

```powershell
python -m research.scoring --rmse 30 --baseline-rmse 50 --f1 0.8 --baseline-f1 0.6
```

Отчет тестового прогона находится в `reports/benchmark/summary.json`; при запуске одной задачи — в ее `metrics.json`. `outer_split.json` хранит индексы и отпечаток исходных данных, `agent.log` — протокол, `holdout_truth.csv` используется только внешним оценщиком.

## Сборка

```powershell
python tools/build_submission.py
```

Результат — `dist/submission.zip`, с `solution.py` в корне и SHA256 рядом. Скрипт проверяет синтаксис Python, целостность ZIP и состав архива. Сборка воспроизводима при неизменных исходниках. Перед отправкой нужен прогон с выданным Qwen и проверка на платформе; архив автоматически никуда не отправляется.

Проверка готового CSV: `python tools/verify_submission.py path/to/task.md`. `tools/refit.py task.md report.json` переобучает выбранные на собственном validation конфигурации на полном train той же задачи. Он не выбирает параметры по внешнему holdout. `tools/predict.py manifest.json input.csv output.csv` использует уже сохраненные модели без нового обучения.

Для локального контейнера:

```powershell
docker build -t tabular-research .
docker run --rm --cpus=8 --memory=32g --env-file .env -v "C:\path\to\task:/task" tabular-research /task/task.md
```

`Dockerfile` предназначен для локальной проверки; платформа использует собственный контейнер. Сеть во время обучения не нужна, кроме разрешенного организаторами доступа к Qwen API. Предобученные ML-веса и внешние обучающие данные не используются.
